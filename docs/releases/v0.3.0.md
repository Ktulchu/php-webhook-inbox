# PHP Webhook Inbox v0.3.0

Yii3 PostgreSQL support for the framework-independent transactional webhook inbox.

## Highlights

- Add optional `Yii3Adapter` for the host application's Yii DB 2 PostgreSQL connection (`yiisoft/db-pgsql:^2.0`).
- Keep Inbox, worker and handler writes on the same physical PostgreSQL session.
- Reject webhook admission inside caller-owned Yii3 or native PDO transactions without committing or rolling them back.
- Support named parameters, `INSERT ... RETURNING`, savepoint recovery after SQL errors and concurrent worker claiming with `FOR UPDATE SKIP LOCKED`.
- Add Yii3 adapter contract tests and a dedicated PostgreSQL 17 CI job.
- Update tagged-release installation instructions and the Yii3 integration guide.

## Validation

The Yii3 adapter was also exercised in a separate, real Yii3 web application with PHP 8.5.12, Yii DB 2.1.0, `yiisoft/db-pgsql` 2.0.1 and PostgreSQL 17.12. Checks covered admission and deduplication, same-session business effects, commit/rollback, external Yii3/PDO transactions, SQL savepoint recovery, retries, two independent worker processes and signed HTTP requests including database failure responses.

## Installation

Once this release is available on Packagist, run in your existing Yii3 application:

```bash
composer require 'ktulchu/php-webhook-inbox:^0.3' 'yiisoft/db-pgsql:^2.0'
```

If the package or tag is not yet available on Packagist, use GitHub as the Composer VCS source:

```bash
composer config repositories.webhook-inbox vcs https://github.com/Ktulchu/php-webhook-inbox.git
composer require 'ktulchu/php-webhook-inbox:^0.3' 'yiisoft/db-pgsql:^2.0'
```

Commit the consuming application's `composer.lock`. GitHub publication and Packagist registration/indexing are separate steps.

## Compatibility and scope

PHP 8.3+, PostgreSQL 16+ and Composer 2 remain required. Yii3 packages are optional: PDO, Yii2 and Doctrine DBAL 4 consumers do not need to install Yii3. No core API or schema migration changes are required for this release.

Handlers must use the worker's connection and keep effects database-local. The bundled Receiver HMAC is a test protocol, not a verifier for a real payment or webhook provider. This remains an early release without claims of remote exactly-once effects or a security audit.
