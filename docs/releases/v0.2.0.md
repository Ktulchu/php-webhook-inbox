# PHP Webhook Inbox v0.2.0

First publicly tagged release of a small framework-independent, PostgreSQL-only transactional webhook inbox.

## Highlights

- Installable Composer library for PHP 8.3+, PostgreSQL 16+; PSR-4 autoloading and an independent Composer consumer.
- Small `ConnectionInterface` plus optional adapters for native PDO, Yii2 and Doctrine DBAL 4; no framework dependency in the core.
- Safe Yii2 master routing for `INSERT ... RETURNING` and fresh deduplication reads, without query caching, including configurations with read replicas.
- Reject HTTP webhook admission inside an externally owned database transaction to avoid false HTTP 202 followed by rollback.
- Durable `(source, event_id)` deduplication, concurrent worker claiming with `FOR UPDATE SKIP LOCKED`, rollback-to-savepoint on handler errors, bounded retries and DB-local atomic effects.
- Docker demonstration; documented plain PHP, Yii2 and Symfony examples and security/transaction limitations.

## Compatibility and scope

This is an **early release**. PHP 8.3+ and PostgreSQL 16+ are tested targets. Yii2 and Doctrine DBAL 4 are optional host dependencies; PDO requires `ext-pdo` and `ext-pdo_pgsql`. The library does not implement webhook provider-specific signatures, queue brokers, failed-event redrive, monitoring or remote exactly-once effects. The provided HMAC Receiver is a *demo protocol*, not a payment-provider integration. See the [README](../../README.md) and [integration guide](../integration.md) before deploying.

## Installation

After the repository is registered with Packagist, use:

```bash
composer require 'ktulchu/php-webhook-inbox:^0.2'
```

Until then, add the repository as a Composer VCS source:

```bash
composer config repositories.webhook-inbox vcs https://github.com/Ktulchu/php-webhook-inbox.git
composer require 'ktulchu/php-webhook-inbox:^0.2'
```

Packagist package registration is a separate step from creating this GitHub release.
